# UI/UX 后续推进计划：游戏感与视觉品质

> 制定日期：2026-08-07
>
> 前提：PC / iPad / 移动端三端可玩性优化已基本完成，游戏界面达到"可用"水平。本文档聚焦如何从"可用"推进到"有游戏感、接近商业作品质感"，给出方向抉择、分阶段路线与可执行的实施清单。
>
> 与 `UI_OPTIMIZATION_PLAN.md` 的关系：前者是 2026-07-26 的全量审计 + 6 阶段整改计划（美术素材 / 动效 / 音效 / 新手引导 / 响应式 / 技术债），本文档在其基础上**聚焦"游戏感反馈层"与"视觉品质层"的系统化落地**，并对"是否引入 Three.js"这一架构决策给出明确判断。

## 1. 方向抉择：为什么不引入 Three.js

《富饶之城》是 **2D 卡牌 / 桌面游戏**，视觉核心是卡牌、金币、角色、城区。引入 `three.js` + `@react-three/fiber` 的 ROI 极低：

| 维度 | 风险 |
|------|------|
| 包体积 | `three` + `@react-three/fiber` + `drei` 至少 +600KB gzip，首屏阻塞 |
| 性能 | WebGL 渲染管线在移动端 / iPad 低端机型掉帧风险高，与已完成的性能优化冲突 |
| 架构 | 卡牌纹理、UI 面板、交互流需在 2D DOM 与 3D 场景间反复切换，维护成本爆炸 |
| 效果 | 卡牌游戏 3D 化容易产生"Unity 移植 HTML5 的廉价感"，而非成熟卡牌游戏的质感 |

**结论**：卡牌游戏的视觉精细主要来自 **2D 画面的光影、动效、反馈节奏**，而非 3D。本计划不引入 Three.js，所有动效与视觉提升基于现有 CSS / SVG / Web Audio API 实现，**零新增 npm 依赖**。

### 3.1 阶段一：游戏感反馈层（最高优先级）

**核心原则**：每一个游戏状态变化 = 一个动效 + 一个音效。让玩家"感到"游戏在响应自己的操作，而不是看静态文字变化。

#### 反馈矩阵

| 游戏事件 | 视觉动效 | 音效 | 触发点（现有代码） |
|----------|----------|------|--------------------|
| 轮到自己行动 | 角色卡 `scale(1.05)` + 金色光晕脉冲 0.6s | 升调"叮"（已有 `playTurnSound`） | `BoardScreen.tsx` 回合切换 |
| 揭示身份卡 | 3D 翻牌 `rotateY(180deg)` + 短暂模糊淡出 | 木质翻页 + 鼓点 | `CharacterCard.tsx` 角色揭示 |
| 抽一张手牌 | 卡堆飞出，弧线落到手中，轻微 bounce | 轻快滑动声 | `PlayerHand.tsx` 手牌更新 |
| 建造城区 | 卡牌从手牌飞向城区槽位，落定后发光 0.5s | 石料落地 + 共鸣 | `PlayerCity.tsx` / `SeatPanel.tsx` 建造 |
| 获得金币 | 金币图标飞入角色金币堆，数字跳动 +1 | 金币碰撞声 | `SeatPanel.tsx` 金币变化 |
| 交税 / 收税 | 金币从税收源"流向"目标玩家 | 硬币滚动声 | `ActionExecutor` 收税动作 |
| 被刺杀 | 角色卡红色闪烁 + 破碎粒子 | 金属断裂 | `CharacterCard.tsx` 💀 印章 |
| 被偷窃 | 金币抖动 + 减号飘字 | 低沉"嗡" | `SeatPanel.tsx` 💰 印章 |
| 魔法换牌 | 手牌旋转洗牌过渡 | 高频 sweep | `PlayerHand.tsx` 换牌 |
| 回合切换 | `TurnOrderBar` 横向滑动高亮过渡 | 切换 click | `TurnOrderBar.tsx` |
| 倒计时剩余 10s | 计时条红色脉冲 | 低频 tick | `TurnTimer` 倒计时 |
| 游戏结束 | 胜方卡牌升起 + 金色粒子爆发 + 背景缩放 | 胜利号角琶音 | `EndGameModal.tsx` |

#### 动效约束

- 所有动效 ≤ 400ms，**不阻塞操作**（卡牌游戏信息密度高，动效过长会让熟练玩家烦躁）
- 全部合成音（Web Audio API），不加载 mp3，首屏零阻塞
- **必须尊重 `prefers-reduced-motion`**：动效降级为直接切换，音效保留
- 动效服务于玩家对游戏状态变化的理解，**不为动而动**

#### 代码落地建议

`utils/sound.ts` 扩展（继续零依赖合成，不引入 Howler / Tone.js）：

```typescript
export const sfx = {
  turn: playTurnSound,
  flip: () => { /* 合成翻页 + 低频鼓点 */ },
  build: () => { /* 两段式：滑入 + 共鸣 */ },
  coin: () => { /* 两金币碰撞 click */ },
  death: () => { /* 低频渐弱 */ },
  magic: () => { /* 高频 sweep */ },
  win: () => { /* 三音阶上行琶音 */ },
};
```

`_tokens.scss` 新增游戏感 token：

```scss
:root {
  // 动画时长 — 卡牌游戏偏利落，不拖沓
  --dur-fast: 160ms;
  --dur-base: 260ms;
  --dur-slow: 420ms;
  --ease-out-back: cubic-bezier(0.34, 1.56, 0.64, 1);
  --ease-in-out: cubic-bezier(0.4, 0, 0.2, 1);

  // 游戏色（与城区类型呼应：宗教-金、军事-红、商业-蓝、政治-紫）
  --gold: #d4af37;
  --gold-glow: 0 0 16px rgba(212, 175, 55, 0.55);
  --danger-glow: 0 0 14px rgba(220, 53, 69, 0.55);
}
```

### 3.2 阶段二：视觉品质层

解决"看起来像 demo"的问题，完全不需要 3D。

#### 3.2.1 卡牌光影质感

- 所有卡牌加 `inset 0 0 20px rgba(0,0,0,0.25)` 内阴影 + 左上 35° 高光渐变 → 立体质感
- hover 时 `transform: translateY(-3px) rotateX(2deg)` 微倾斜 + 金色投影
- 已建造城区卡加 `filter: saturate(1.2) brightness(1.1)`，未建造灰调 → 视觉区分

#### 3.2.2 面板层次感

- 所有浮层（角色选择、操作面板）加柔边阴影 `box-shadow: 0 20px 60px rgba(0,0,0,0.45), 0 0 0 1px rgba(212,175,55,0.15)`
- 面板切换用 `backdrop-filter: blur(8px)` 毛玻璃（注意 Safari 兼容性兜底）
- 统一面板圆角 `--radius-panel: 14px`（比 Bootstrap 0.25rem 游戏化得多）

#### 3.2.3 配色精修

- 建立 `citadels` 专属色板（中世纪金 + 深棕 + 酒红 + 宝石蓝），替换现有 Bootstrap 默认色
- 城区卡片按类型分配色系：
  - 宗教 → 金 / 奶白
  - 军事 → 铁灰 / 红
  - 商业 → 蓝 / 琥珀
  - 政治 → 紫 / 金
- 让玩家**一眼识别**城区类型
- 角色头像加统一圆形金边或暗银描边

#### 3.2.4 字体层级

- 标题用带衬线字体（Cinzel / Cormorant Garamond Web 字体）→ 中世纪城堡感
- 正文用 Inter / 系统字体 → 可读性

### 3.3 阶段三：氛围层（锦上添花，非必需）

1. **游戏主页面背景**：把现有 `ParticleField` 升级为"金色烛火 + 烟雾 + 微光"粒子层，叠加缓慢平移的城堡剪影 SVG
2. **胜利庆祝**：结束时触发 80 粒子金色爆发 + 胜方卡牌升起 + Web Audio 号角琶音
3. **过场动画**：每回合开始有一个 200ms 的"页面边缘金色扫光"过渡
4. **全局设置页**：加音量滑块 + 动效开关 + 主题切换（金 / 深棕 / 暗夜蓝两套）

## 4. 实施节奏与优先级

按"玩家感知强度 × 实现成本"排序，第一批做这 5 件事（覆盖 80% 游戏感）：

| 序号 | 事件 | 感知强度 | 成本 | 备注 |
|------|------|----------|------|------|
| 1 | 卡牌翻牌动效 + 对应音效 | 极高 | 中 | 选角色时最核心的"仪式感" |
| 2 | 建造城区落定动效 + 金币飞入音效 | 极高 | 中 | 玩家最常做的动作 |
| 3 | 轮到自己时的角色卡高亮 + 音效 | 高 | 低 | 循环最多的反馈 |
| 4 | 金币数量变化的跳动动画 | 高 | 低 | 核心资源变化 |
| 5 | 胜利庆祝的粒子爆发 + 号角琶音 | 高 | 中 | 最后的记忆点 |

这 5 项做完，游戏感会有数量级提升，代码改动量小，只涉及：

- `utils/sound.ts` 扩展 5~8 个合成函数
- `_animation.scss` 新增 6~8 个 keyframes
- 各卡牌 / 角色组件加 `onXxx` 回调触发动效
- 不新增任何 npm 依赖

## 5. 技术约束与原则

### 5.1 动效原则

- **服务状态理解**：每个动效都要服务于玩家对游戏状态变化的理解，不能为动而动
- **时长克制**：≤ 400ms，不阻塞操作
- **降级友好**：`prefers-reduced-motion` 下动效降级为直接切换
- **性能优先**：优先 `transform` / `opacity`，避免触发 layout

### 5.2 音效原则

- **零依赖合成**：继续用 Web Audio API，不引入 Howler / Tone.js
- **零二进制资源**：不加载 mp3，首屏零阻塞，iOS 友好
- **用户可控**：必须有开关与音量控制（阶段三设置页）
- **不扰民**：音量偏轻，可被系统静音覆盖

### 5.3 与现有计划的关系

- 本计划的阶段一对应 `UI_OPTIMIZATION_PLAN.md` 的 Phase 2（动效）+ Phase 3（音效），但**合并为统一的"反馈层"推进**，强调动效与音效的配对设计
- 本计划的阶段二对应 `UI_OPTIMIZATION_PLAN.md` 的 Phase 1（美术地基）的延伸，聚焦光影与配色而非素材本身
- `UI_OPTIMIZATION_PLAN.md` 的 Phase 0（快速胜利）应优先完成，本计划在其基础上推进

### 5.4 项目记忆约束

- 所有模态框统一使用共享的深色 `.app-modal` 样式类（阶段二面板层次感须遵循）
- Zustand selector 必须返回稳定引用，禁止 `{...x}` 展开（阶段三设置 store 须遵守）
- 必须用 `createBrowserRouter + RouterProvider`（动效若涉及路由过渡须注意）
- 自定义 dropdown 组件用 `React.createPortal` 渲染到 `document.body`（阶段二若有下拉控件须遵循）
